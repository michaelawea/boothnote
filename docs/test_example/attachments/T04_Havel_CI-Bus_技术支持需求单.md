## 1. 测试背景

Havel 正在进行第一轮样品台架测试。样品可以正常上电，测试设备可以观察到 CAN 总线流量，但目前无法确认通信端口接线是否正确，也无法稳定解析 SOC、SOH 和告警状态。

## 3. 客户问题

### 3.1 通信端口文档

客户需要确认：

- 通信端口在电池上的位置和方向；
- 连接器品牌、系列和配套端子料号；
- 插拔、密封与安装注意事项；
- 是否允许与其他 CAN 节点共用同一总线。

### 3.2 Pin 脚与电气接口

客户需要一份可执行接线的 Pin 表，至少包括：

- CAN-H、CAN-L、Signal GND、Shield/Reserved 的位置；
- 每个 Pin 的允许电压范围和反接保护说明；
- 电池内部是否带 120Ω 终端电阻；
- 屏蔽层应该单端接地还是双端接地；
- 接线错误时是否存在损坏风险。

该项优先级最高，希望在 2026-08-12 前得到确认。

### 3.3 CI-Bus 通信协议

客户需要：

- 总线波特率和节点角色；
- 报文 ID、发送方向、发送周期和超时策略；
- 字节序、起始位、长度、缩放系数和偏移量；
- SOC、SOH、电压、电流、温度、充放电允许状态和告警状态的定义；
- 上电握手、休眠、唤醒和通信中断恢复流程；
- 示例报文及解析结果；
- 若有 DBC 文件，说明版本号和适用固件版本。

### 3.4 测试代码

客户希望获得一份最小可运行示例，要求：

- 支持 Ubuntu 24.04、Python 3.12 和 SocketCAN；
- 默认读取 `can0`，波特率为 500 kbit/s；
- 能打印时间戳、报文 ID、DLC 和十六进制数据；
- 至少演示解析 SOC 与一个告警字段；
- 包含依赖安装、启动命令、预期输出和常见错误处理；
- 示例代码不得包含真实客户密钥或生产凭据。

## 4. 已观察现象

1. 总线上可以看到 `0x351` 与 `0x355` 周期报文；
2. 客户现有解析工具未显示 SOC；
3. 告警状态显示为未知值；
4. 暂无证据表明电池没有发送数据，也暂无证据表明电池硬件故障；
5. 当前最可能的排查方向是接线定义、字节序、缩放系数或协议版本不一致，但均未形成结论。

## 6. 验收标准

- 客户可以依据 Pin 表完成接线，并明确终端电阻配置；
- 测试脚本能够在指定环境中启动并读取 `can0`；
- 对同一帧示例报文，双方解析出的 SOC 和告警状态一致；
- 协议文档版本与样品固件版本匹配；
- 所有未确认项都有负责人和后续确认日期。
