## 0. 三层，按「碰什么」分，不按「测什么」分

分层的依据是**副作用**，因为这决定了哪一层能对生产跑。

| 层 | 碰什么 | 数量 | 耗时 | 能对生产跑 |
|---|---|---|---|---|
| **单元** | 不碰网络、不碰进程外的东西 | 245（PWA 91 · 网关 61 · agent 93） | ~1 s | ✅ 安全 |
| **集成** | 真 HTTP + **真库** —— 默认是**一次性**的那套（D101） | 148 | ~35 s | 🔴 **不行，脚本硬拒绝非 localhost** |
| **冒烟** | 只读 curl | 15 项 | ~5 s | ✅ **部署后必跑** |

⚠️ 单元那一行原来写的是「什么都不碰」，2026-08-10 起不准确了：
`sync.test.ts` 里跑的是**真的 Dexie**（IndexedDB 由 `fake-indexeddb` 在进程内实现）。
判据没变 —— 它仍然不碰网络、不碰任何进程外的东西，所以对生产完全安全、随时能跑。
**分层看的是副作用能不能跑出这个进程，不是「用没用真实现」。**

```bash
./scripts/test.sh              # 单元。改代码时随手跑
./scripts/test.sh all          # 单元 + 集成
./scripts/test.sh integration  # 只跑集成（一次性环境，跑完什么都不留）
./scripts/test.sh scenarios   # docs/test_example 的 T01–T05 业务验收（真调模型，2 分钟）
./scripts/test.sh smoke        # 本地冒烟
./scripts/smoke.sh https://capture.example.com https://crm.example.com
```

### `apps/capture-pwa/src/__tests__/sync.test.ts`（30 个，D100）

**三段解耦的第一段** —— 「速记 → 本地 IndexedDB → 网关 `inbox`」这一段里 `sync.ts` 是唯一的搬运工。
它错了的后果不是界面不好看，是**展会现场录的话丢了**。这也是 T8②「断网补传」唯一的自动化覆盖。

跑的是真 Dexie（`fake-indexeddb`），只把网络那一侧换成桩（`XMLHttpRequest` / `fetch` /
`localStorage` / `navigator.onLine`）。**mock 掉 `db` 验不了「东西是不是真的落住了」**，
而这条链路上出过的事故全在后者：`.where(x)` 的 x 没进索引 → Dexie 抛异常 → 调用点吞掉 →
界面完全正常、数据永远推不上去（`db.ts` 里记着这个错犯过四次）。

| 组 | 里面最要紧的一条 |
|---|---|
| ① 断网→落库→回网 | 离线时一个请求都不发，**也不计次数**（断网十分钟不该烧完重试预算） |
| ② 失败之后 | 🔴 音频**一个字节都不能少** —— 展会 10 天说过的话不可再生 |
| ③ 登录失效 | 🔴 401 保持 `queued`、不计次数、当场停下。当成普通失败的话 8 次很快烧完，**那时数据还在本地却再也传不上去** |
| ④ 卡在 `syncing` | 启动时掰回 `queued`；`flush` 自己也捞它（否则既不重传也不显示，凭空消失） |
| ⑤ 重入 | 上一轮还在飞时第二轮让路 |
| ⑥ 改正文 | 🔴 绝不把 `sync` 打回 `queued` —— 音频已从本地删掉，重传等于**用一条没音频的记录覆盖一条有音频的** |
| ⑦ 下行合并 | 🔴 本地还在队列里的**整行一个字段都不动**；本地有未推的修改时不覆盖；服务端状态每次都覆盖 |

🔴 **这一组是用变异测试验收的**：对 `sync.ts` 做 8 处破坏，7 处当场被抓、**1 处漏网**——
漏的那条断言的是「`text`/`sync`/`remoteId` 三样没变」，而删掉守卫后走的分支本来就不碰这三样，
于是它是个恒真命题。改成按字面断言**整行相等**才真的抓得住（§2.41）。
**一条测试是绿的，不证明它在测什么。**

## 2. 集成测试

`services/gateway/src/__tests__/api.test.ts` —— 真 HTTP + 真库。
**它测的全是那些「文档里写了但没验过」的约束。**

### 前置：没有前置（D101）

```bash
./scripts/test.sh integration     # 就这一条。要 docker，别的什么都不用先起
```

**它在一次性环境里跑，你自己那套（`boothnote` 库 / Twenty / 4000 端口上的网关）一个字节都不碰。**

| | |
|---|---|
| 库 | 一次性 Postgres 容器，端口临时挑，`trap EXIT` 保证怎么退出都 `docker rm -f` |
| 网关 | 一次性进程，临时端口 |
| Twenty | `SERVER_URL` 指向**不通的端口** → **一条 CRM 记录都不会建**（NEEDS_TWENTY 显式 skip） |
| 模型 | `AGENT_ENABLED=0` + 占位 key → **一次都不烧** |

实测：跑前 `inbox/app_user/staging = 27/4/27` → 跑完 133 条用例 → **27/4/27**。

🔴 **拿不到 docker 就 exit 1，绝不「退回用你现在那个库」** ——
静默降级会让「我以为它是隔离的」和「它其实写进了我的库」长得一模一样。

**另外两档（都会留数据，所以都要显式写出来）：**

```bash
./scripts/test.sh integration --here           # 对着你现在开着的那套跑（末尾 purge）
./scripts/integration-stack.sh --with-twenty   # 一次性库 + 连本地 Twenty（销毁库之前自动 purge）
./scripts/integration-stack.sh -- --test-name-pattern=重录   # -- 之后原样传给 node --test
```

⚠️ `--with-twenty` 有一道硬闸门：**`SERVER_URL` 不是 localhost 就 exit 1**。
线上的 CRM 一条都不许写 —— 要验生产只能用只读的 `smoke.sh`。

⚠️ 走 `--here` 时注意两件：**别在已经有网关连着同一个库时再起第二个**
（两个心跳抢同一批 `staging`，一堆用例卡在 `committing`，实测踩过）；
以及管理台那条暴力破解用例跑完会把本机 IP 锁 15 分钟（锁记在网关内存里，
一次性网关每轮换进程所以无所谓）。

### 🔴 安全闸门

测试会**建账号、发速记、往 CRM 写真记录**，所以代码里写死：

```
GATEWAY_URL 与 APP_DATABASE_URL 必须都指向 localhost，否则直接 exit 1
```

不是靠人记得，是靠代码拦住。生产用只读的 `smoke.sh`。

🔴 **绕过它必须把目标主机名原样写出来，`=1` 不管用**（2026-08-10 收紧）：

```bash
ALLOW_NONLOCAL_TESTS=staging.example.com:4000 node --test …   # ✅ 只对这一个目标有效
ALLOW_NONLOCAL_TESTS=1 …                                      # 🔴 不再放行任何目标
```

理由很实在：一个写进 shell profile / CI 变量里的 `1`，会在**你完全没想起它**的那天放行生产。

## 3.5 四道 tsc 抓不到的机械守卫

这四个都不测「功能对不对」，测的是「有没有踩到某一类**类型完全正确**的坑」。

> 🔴 **接守卫的时候，必须让它红一次再走。**
> 2026-08-10 实测：`check-i18n-safety.mjs` 那一行是**裸调用**，脚本里 `set -uo pipefail` 没有 `-e`，
> 于是它 exit 1 之后 `FAILED` 还是 0，`test.sh` 照样打「✅ 全部通过」——
> **D80 那道守卫接上去三天，一次都没生效过。**
> `test.sh` 里调外部脚本一律要用 `run`（它才收退出码），和 `into` 收子 shell 退出码是同一件事。

### `scripts/check-schema-drift.mjs`（接在 `./scripts/test.sh` 里，D99）

改 `twenty-schema.mjs` 的后果分成三档，而它们在 diff 里长得一模一样：

| 改什么 | 后果 |
|---|---|
| `label` / `color` / `description` / `icon` | 🟢 安全。D78 那 210 条双语标签就是这么上的 |
| 字段 `name` / 对象 `nameSingular` | 🔴 provision 会**新建一列**，线上老那列的数据从此没人读 |
| 枚举 `value` | 🔴 线上老值被原样留着，但白名单和视图只认新值 —— 已有记录**在那些地方集体消失** |
| `type` / 关系 `target` / `isUnique` | 🔴 provision 对已存在的字段不动这几样，SPEC 和线上从此对不上，而它下次跑还是绿的 |

后三档**全程 HTTP 200、日志里一个字都没有**（§2.28 就是这么丢的数据）。
所以基线 `scripts/schema-snapshot.json` 只记这几样，**label 一概不记**——
每次改文案都红一下的检查活不过两周。

- **消失 / 签名变了 → exit 1**；**新增 → 只提示一行，exit 0**（加字段是天天在做的事，
  让它也阻断的话 `--update` 就变成橡皮图章，真正危险的改名会被顺手盖过去）
- 两条**不依赖基线**的绝对判据，连 `--update` 都挡：两个枚举 value 规范化后撞车（线上只会剩一个）·
  `FIELD_UPDATES` 的 `defaultValue` 不在自己的 options 里
- 快照存**规范化之后**的值（`SAMPLE_TESTING` 而不是 `sampleTesting`）—— 那才是线上真正那串字符
- 确认改动是有意的：`node scripts/check-schema-drift.mjs --update`。
  **红了先别急着 update** —— 先回答「线上已有数据的那一列，改名之后谁去搬」

### `scripts/check-i18n-safety.mjs`（接在 `./scripts/test.sh` 里，D80）

| 守什么 | 为什么 |
|---|---|
| 🔴 **数据路径里不许出现 `t()`** | 真踩过：`sync.ts` 把译文写进了 IndexedDB —— **同一份数据会因为界面语言而不同，还可能被推到只增不改的 `inbox`** |
| **不许拿译文做比较** | 语言一换判断就失效 |
| **`t()` 不许在模块级求值** | 语言是运行时才确定的；模块常量在 import 那一刻求值，拿到的是旧语言 |

**tsc 对这三类完全无感** —— 类型是正确的，错的是语义。

### `scripts/i18n-report.mjs --check`（接在 `./scripts/test.sh` 里，D113）

上面那道守「换语言别改数据」，这一道守「**换了语言真的换了**」—— 两件事。

2026-08-11 维护者 真机报：英文账号下「还没问过的」的问题、「已经知道的」的细节、
「第 N 次问」「还有 N 项（不急着今天问）」全是中文。而当时的 `i18n-report.mjs`
报 **82%**，且 **`test.sh` 里根本没有它**，只有人想起来才跑一次。

| 它现在怎么判 | 为什么 |
|---|---|
| **按「字典里查得到译文」算覆盖率** | 旧版数的是「有几处调用了 `t()`」，从不回头查那条中文在字典里有没有。**「调用了翻译函数」不等于「翻得出来」** |
| **单独抓 JSX 文本节点里的裸中文** | `<span>第 {wave} 次问</span>` 这类根本没走 `t()`，**补字典也修不好，得改代码**。用户报的三条里有两条是这一类（共 34 处） |
| **中文标点也算中文** | `t('。')` / `「{a}」` 一个汉字都没有，只认 `[一-鿿]` 的话它们在统计里**根本不存在** |
| **覆盖率向下取整** | 529/531 四舍五入是 100%，而那 2 条真会显示中文 |
| 逃生口 | 行尾 `// i18n-ignore` + 写清理由（现在只有 `mock-data.ts` 的原型残留用了） |

🔴 **它守不住的两件事，别把它的绿当成全部：**

1. **「字典里有」不等于「那一行过了 `t()`」。** 这是故意的 —— 标签表
   （`{ pending: '待整理' }`）是在渲染处才过 `t()` 的。代价是 `join('、')`
   这种漏网它抓不到。**写这一轮时实测栽过一次**：往字典里加了 `'、'`，
   脚本当场变绿，而那一行根本没调 `t()`。**加条目前先去调用点确认。**
2. **服务端给的中文它一个字看不见。** `/enums`、`/gaps`、`/staging/:id/targets`
   的 label 都在网关里生成，PWA 源码里只有一个 `{a}`。那几处只能靠
   `labelsFor(locale, …)` 在服务端做。**扫源码的守卫只能守住源码里的东西。**

⚠️ **量之前先验尺子。** 写这一版时第一版的 key 解析只认 `'中文':` 和裸 key，
**漏掉 148 条 `"中文":`**，于是它报「覆盖率 32%、缺 338 条」——
一个吓人但是假的数字，差点照着它把已经翻好的东西再翻一遍（真实起点是 87%）。
拿几个一定存在的 key（`取消` / `关闭` / `返回`）assert 一遍解析结果，再信它报的数。

**怎么在浏览器里真看一眼英文界面**（不需要账号，也不改产品代码）：

```
① .claude/launch.json 里临时加一档：
   runtimeExecutable "env"，runtimeArgs 前面塞 "VITE_GATEWAY_ORIGIN=http://127.0.0.1:9"，
   端口挑一个没人用的（5199 + --strictPort）
② 打开页面，控制台里塞一个假登录态：
   localStorage.setItem('boothnote-session', JSON.stringify({
     token: 'x', user: { userCode: 'x', displayName: 'x', role: 'admin', locale: 'en' }}))
③ 刷新
```

能成立是因为 `revalidate()` **只在 401 时登出**，网络不通就静默保留登录态
（离线优先，展馆断网不能把人踢下线）—— 指向一个死端口就得到「一直离线」。
要看某一屏的真实数据就在控制台里 stub `window.fetch`。**验完把那一档删掉。**

### `scripts/data-guard.mjs`（接在 `deploy.sh` / `deploy-server.sh` 里，D79/D82）

问的问题和 `verify-deploy.mjs` **不一样**：那个问「配置生效了没有」，这个问「数据还在不在」。
§2.28 那次数据被清空时，前者是绿的。

- 变更前拍快照（每个对象行数 + 每个 SELECT 字段的非空计数与取值分布），出口再拍一次逐条对，
  **任何一格非空计数下降就中止部署**
- 卡两道：`provision-twenty` 之后 / `import-accounts --backfill` 之前各一道，出口一道 ——
  **判据：对账要卡在「可能弄坏它的那一步」和「可能掩盖它的那一步」之间**
- 绝对判据（不依赖历史）：对象有记录、而某枚举字段非空率 0% → 告警不阻断
- 退出码三档：0 没掉 / 1 掉了中止 / 2 没基线跳过

## CI 里没有 Twenty —— 所以有 18 条会 skip

CI 只起 **Postgres + 网关**，`TWENTY_API_KEY` 是个占位串。
不给它装 Twenty 是刻意的：那要 4 个容器跑三五分钟，而且要一个
**只有 维护者 能生成**的 API key（CLAUDE.md 的硬规则）。

于是要真写 CRM 的断言在 CI 里必然 `fetch failed`。处理方式是
**`skip` 而不是提前 `return`**：

| 做法 | CI 上看到的 | 问题 |
|---|---|---|
| `if (!company) return;` | `67 passed` | **绿着，其实什么都没测**。2026-08-03 之前就是这样 |
| `it(name, NEEDS_TWENTY, …)` | `67 tests · 49 pass · 18 skipped` | 总数不变，跳过的明确写出来 |

**总数必须保持 67。** 用 `describe` 级 skip 会把整块从计数里抹掉（67 → 51），
而「测试数悄悄少了 16 条」是没有人会注意到的那种变化。

这一层只有本地跑 `./scripts/test.sh all`（Twenty 开着）才覆盖得到。

⚠️ **`api.test.ts` 有一条偶发红的用例**（`在位品牌 · 阶段 · 决策窗口 都有落点`）——
`node --test` 并发跑 describe，而 D56 规定「同一家 + 同一品类 = 同一条商机」，
多条用例都拿名单里第一家做被试，会互相踩。单独跑必绿，理由写在那条用例上面。
