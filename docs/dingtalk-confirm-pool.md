# 钉钉：自动入库 + 60 秒撤回 + 二轮对话 —— 定稿

> 状态：**定稿（2026-10-01，维护者 拍板）· P1 实现中。** T107 · D143–D148。
> 前身是「确认链接 + 待修改池」方案（3 份独立方案 + 2 份评审），维护者 改成「不做确认、只做撤回」以减少复杂度。
> 漂移检查（§00.4）：服务 **C2 / C3**（在钉钉里记、在钉钉里更新）。C4：人在钉钉里**零必需操作** —— 不点就入库。

## 0. 一句话

**@ 一句 → 速记整理 → 汇报（状态先行）→ 够完整就 60 秒后自动写入 CRM，期间点链接可撤回；
不够完整就挡住、问一句，回答后再走一遍。** PWA 那条路不变（仍要人确认）。

## 1. 流程

| # | 时机 | 发生什么 | 群里看到 |
|---|---|---|---|
| 1 | 同步 | 命令层 → 显式指向（`#N` / 待回答问题 / 更正词）→ 否则路由器 | `已接收 · 转给速记（新记录）` / `已接收 · 转给速记（修改 #128）` / `已接收 · 转给实验室助手` |
| 2 | 异步 | agent 跑完 → **确信度门槛**（§3） | — |
| 3a | 过门槛 | **占位排队**（心跳认领不到）→ 发汇报 + 撤回链接 → **送达才开始 60 秒倒计时**；没送达 / 中途出错就撤掉占位 | `#128 选型情报 · 待入库` |
| 3b | 没过 | 发汇报，状态写「未入库 · 缺 X」，登记一个待回答问题 | `#128 选型情报 · 未入库` |
| 4 | 60 秒到 | 心跳提交 → 群里回一行 | `#128 · 已入库：新建 拜访 1、选型情报 1；更新 商机 1` |
| 5 | 点撤回 | 取消排队，CRM 一个字没写 | `#128 · 已撤回，未写入 CRM` |
| 6 | 再 @ 命中 #128 | 同一条对话出新一版 → 回到 2；上一版若在倒计时，**先取消** | 新汇报，带「本版变更」 |

## 2. 撤回链接

| 项 | 定稿 | 理由 |
|---|---|---|
| 形态 | `https://<CAPTURE_DOMAIN>/api/a/<token>`，token = 16 字节随机串，库里只存 sha256（`action_link` 表） | 不透明 token 不碰 JWT（`userFromToken` 不校验 aud）；能力只有「撤回这一次排队」 |
| 绑定 | 绑**某一次排队**（`queue_id`），不是这一版 | 撤回后 `入库 #N` 重新排，旧汇报里的链接撤不掉新的倒计时 |
| 没配公网地址 | 签不出链接 → **不自动入库**（不可撤回的倒计时不排），汇报说清、要人 `入库 #N` | 启动横幅会喊出来 |
| GET / POST | GET 只出页面（状态 + 倒计时 + 「撤回」按钮），**只有 POST 有副作用** | 钉钉生成链接卡片、杀毒扫描都是 GET |
| 时效 | 只在倒计时内有用；过了页面写「已入库，要改请 @我 #128 + 修改内容」 | 撤回 = 取消排队，入库后没有可取消的东西 |
| 谁能点 | 拿到链接的人（链接证明不了身份）→ 群里回一行 @本人 | 撤回的最坏后果是「没入库」，可恢复：`@我 入库 #128` |
| 页面安全 | 内容一律转义；CSP `default-src 'none'` + 内联白名单 | 汇报里有群里任何人都能塞进来的原话 |

## 3. 确信度门槛（`channels/commitGate.ts`，纯函数，机器判据）

| 级别 | 条件 | 结果 |
|---|---|---|
| **硬挡** | 客户没对上名单（含只提议了新客户）· agent 失败 | 未入库；**`入库 #N` 也不行**（D28：入库前必须有归属） |
| **软挡** | AI 没整理出字段（兜底原文）· 跑到上限可能不全 · 客户识别把握 low · 类型最低字段不全（下表） | 未入库；补一句再跑，或 `@我 入库 #128` 按原样入库 |
| 提示 | 其它字段把握 low · 信息来源是传闻 · agent 的补充问题 | 照常倒计时，汇报里列「待核」 |

另外两种情况也不自动排（`入库 #N` 可以）：**客户变了**（上一版写入的那几条会软删并按新客户重建，汇报逐条列出）·
**同一版第二次汇报**（重跑过、内容可能和上次不同）。把握度读的是 `staging.confidence` 那一列（不在 extracted 里）。

| 记录类型 | 最低字段 |
|---|---|
| 选型情报（默认） | 品类 + 在位品牌 / 型号 / 阶段 / 需求量 / 决策窗口 至少一项；品类把握不能是 low |
| 售后 | 问题描述 + 型号或品类 |
| 项目 / 跟进 | 有项目提案（跟进：项目编号或任务线程） |

## 4. 汇报格式（状态先行、少 emoji、拟写入详尽）

```
#### #128 选型情报 · 待入库
**状态**：待入库，60 秒后自动写入 CRM。[撤回](https://cap…/api/a/…)
**客户**：Alpin（KNA）
**本版变更**（第 2 版）：型号 PowerFlex 3000 → PowerFlex 2000
**拟写入 CRM**
1. 拜访记录 · 新建
2. 选型情报 · 新建 —— 品类 逆变器；在位品牌 Voltaro；型号 PowerFlex 2000；信息来源 本人在场
3. 商机 · 更新「Alpin · 逆变器」—— 阶段 样品/台架测试 → 送样；决策窗口 2026 Q4
**待核**：型号（把握 低）
**要点**：Alpin 想把逆变器从 3000W 换成 2000W，Q4 送样
**待回答**：Q4 送样几台？（@我 直接回答，30 分钟内有效）
撤回只在入库前有效。入库后要改：@我 #128 + 修改内容。
```

- 「拟写入」的新建 / 更新用 `confirm.ts` 同一批查找函数判（`findOpportunity` / `findProjectByCode` / `findWorkItemByCode`）；CRM 查不到时写「新建或更新」。
- 明细截到约 3000 字；渲染器自己留预算，`md()` 的截断永远不触发。「≤8 行」规格作废。
- 回执账键 `receipt:<stagingId>:<rev>`（rev = extracted 指纹），**同时认旧键** `receipt:<stagingId>`，部署后历史回执不重发。

## 5. 二轮对话（服务端记忆，钉钉只递话）

钉钉流程每次 @ 是一个独立请求，只有 6 个字段，**没有会话 ID、消息 ID、引用**；bot 只看得见 @ 它的消息。
所以「这句接在哪条上」全由网关判，规则从上往下、命中即停：

| # | 条件 | 去向 |
|---|---|---|
| 0 | 整句命令：`帮助` · `待办` · `#128`（重发汇报）· `入库 #128` | 命令 |
| 1 | 正文带 `#N`（必须有 `#`） | 那一条；别人的 → 拒绝并说明 |
| 2 | `记：` / `问：` 开头 | 路由器按前缀（`记：` = 强制新记录） |
| 3 | 更正词开头（更正 / 不对 / 改成…，排掉「不对外 / 改成本」这类），2 小时内 | 本人在这个群最近那一条 |
| 4 | 有待回答问题（**一条一个，30 分钟**），且这句不像提问、没点名**别家**客户（同集团不算别家；那一条还没客户时点名就是回答） | **恰好一个** → 那一条；**两个以上** → 不猜，原话存下、请带 #编号 |
| 5 | 其余 | 路由器 → 新记录 / 实验室 / 日常助手 |

接到某一条上时（对那条 thread 取 advisory lock）：

| 那条当前的样子 | 处理 |
|---|---|
| 倒计时中（或还在发汇报的占位） | 先取消排队，再出新一版 |
| 未入库 / 已撤回 | 出新一版（loop 照旧继承上一版） |
| 已入库 | 出新一版，`staging.replaces` 记交接（D108）→ 入库时**原地更新**，不出第二份 |
| 上一句还在整理（含失败了、还会自动重试的） | 原话先存下（含图片），回「#128 上一句还在整理，汇报出来后再改」 |
| 正在写入（几秒） | 同上，回「正在写入，稍后再改」 |

## 7. 验收

单元（逐个加进 `test.sh`）：门槛表驱动 · 汇报渲染（超长时撤回链接仍在第 2 行、@ 在最后）· 指向规则表驱动。
集成（一次性环境）：GET 撤回页不改库 · POST 撤回在窗口内取消、窗口外 409 · 软挡不排队、`入库 #N` 后排队 · 硬挡 `入库 #N` 拒 ·
倒计时中的更正先取消上一版 · 已入库的更正带 `replaces` · 别人的 `#N` 不动 · 旧回执键不重发 · 钉钉来源工具表里没有 intel 工具。
变异：每道守卫单独删一次。**眼睛验收**：真群里走一遍（倒计时、撤回、@ 到人、二轮回答）。
