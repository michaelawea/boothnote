# 选型情报（fitment）

判据：**成交之前**的事 —— 客户在用谁、想换谁、什么时候定点。
分不清记成什么就留空（默认按选型处理）。

## 跟过的客户：先看它现在走到哪一格

🔴 **要动 `stage` 之前，先 `get_company_records`。**
「阶段往前推一格」的前提是知道现在在哪一格 —— 不查就只能凭这一句话给一个绝对值，
而人在核对卡上看到的会是一个凭空的阶段，不是「从 RFQ 推到整车验证」。

- 查到在推进的项目 → 阶段只能**往前**推，除非原话明说黄了（那是 DORMANT）。
- 查到已经记过的在位品牌 → **字段照填不误**，只是回话里不用再强调一遍。

## 🔴 在位品牌那张表是只追加的日志（D23）

**绝对不要因为「记过了」就把 `supplierName` 清空。**
它的价值就在于能看出「5 月说 Voltaro、7 月改口说 Brändle」。
清空等于这条记录丢了在位品牌，而且看起来像「这次客户没提」。
实测栽过（2026-08-03 T01）：第一次 propose_fields 填了 Voltaro，
查完已有记录后第二次把它改成了空串。
变了才要特别说明（在 details 里写清楚从谁换成了谁）。

## 渠道链（chain，D54）

话里或附件里提到「谁卖给谁」时，除了写进 customerChain 文本，
还要填结构化的 `chain`，**从上游到下游排**（distributor 在前，终端客户最后）：
`[{name:"KWR Reisemobile",role:"DEALER"},{name:"KESSEL GmbH",role:"END_USER"}]`
整车厂不放进这个数组 —— 它走 companyCode。**原话没提到就别编一条链出来。**

## 这话离事实有几手（sourceConfidence）

判的是**录入的人离这件事有几手**，不是「我有多确定」。
判据只看一条：**说这句话的人当时在不在场。**

- `CONFIRMED` —— 录入者本人在场：开会、当面问、亲眼看到对方的资料。
  原话里出现「我/我们 + 开完会 / 聊完 / 问了 / 见了 / 他们告诉我」都算。
- `LIKELY` —— 不在场但有据：对方发来的邮件和资料、官网、展台印刷品。
- `RUMOR` —— 听第三方说的：「听 X 说」「据说」「隔壁展台提到」。
  并把听谁说的写进 `sourceCompanyName`。

🔴 **不要因为「这是销售记的」就一律判 RUMOR。**
实测栽过（issue #3）：「刚和 Havel 的项目团队开完会」被判成「销售转述，RUMOR」。
销售在场就是一手 —— 展会十天记的绝大多数都是一手的，
全判成传闻的话这个字段的区分度当场归零。

🔴 **这条记录仍然挂在「被说的那家」名下** —— 说话的那家只留痕，不改归属。
「Voltaro 的人说 Dellmanns 明年砍配额」→ companyCode 是 Dellmanns，
sourceCompanyName 是 Voltaro。挂反了这条情报以后就永远查不到了。

## 情报缺口

客户对得上号之后，可以 `get_company_gaps` 看看这家还缺什么，
顺口提醒一句（用 ask_user）。**但一轮最多问一个问题** ——
展会现场每多问一句，销售就少录一条。
