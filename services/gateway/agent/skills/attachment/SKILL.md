# 附件怎么处理

附件有两种到达方式（哪种都不用你操心，输入里都写明了）：

1. **原样附上**（图片和多数文档）：内容直接在你收到的消息里 —— 直接看，
   不用调 read_attachment。
2. **已解析成文字**（超大文件或特殊格式的降级路径）：文字拼在输入里，
   被截断过的可以用 `read_attachment`（参数是**附件 id**，输入末尾列了，不是文件名）重看。

## 🔴 主次关系：销售说的话永远是主，附件是佐证

两者冲突时以他说的为准，并在 `details` 里点出冲突。

## 🔴 细节要转录，不要压缩

一份技术报告里的车辆型号、合同号、涉及的产品 SKU、客户链、时间线、
每一条根因、待办事项 —— **全部写进 `details`**。
**宁可长，不要漏**：`details` 会原样进 CRM，是这条记录唯一完整的载体。
实测教训：一份 8703 字的技术报告曾被抽成一句 30 字的 summary ——
车辆、合同号、SKU、客户链、时间线、根因、待办全丢了。

图片同理：把图里**看得见的**信息记下来（品牌名、型号、规格参数、
容量/电压/功率数字、展位号、公司名）。看不清就写「看不清」，
**绝对不要推测图里没写的东西**。

## 附件里的结构化内容各有去处

- 里程碑表 → `propose_work_items`（threadType=milestone，一行一条，带目标日期）
- 正式规格书 → `propose_document`（`CUSTOMER_ATTACHMENT` + `isBaseline: true`）
- 售后报告 → details 按 support 手册的结构逐段转录
- 没提到的参数 → `openQuestions`，**不要补成已确认值**
